# 评测台 · 使用说明

评测台把评测内核（`assets/js/core/eval.js`）批量跑起来：**用例管理 → 跑评测 → 历史与对比**三个视图，跑完还能用「改进建议」反推提示词该怎么改，再用 A/B 验证确实变好了。

入口：`admin.html#/eval`

---

## 一、用例管理

**用例 = 一组素材（热点 + 商品 + 话题 + 语调）**，跑评测时每个创作风格都会基于它生成一条文案。

| 操作 | 说明 |
| --- | --- |
| 从真实业务数据生成种子用例 | 用当前热点 + 该热点的推荐商品 + 语调，一键生成 6 条 |
| 新增 / 编辑 | 弹窗里选热点、选商品（最多 3 件，第一件为主推）、填话题、选语调与表情强度 |
| 勾选参与 | 每行左侧勾选，只跑勾选中的用例 |
| 删除 / 清空 | 单条删除或整体清空（需确认） |

## 二、跑评测

**配置**：参与的创作风格（标签点选，**没点过时默认全部参与**，与界面上高亮的风格一致）、同时跑几条（默认 3）、每条重复几次、是否启用模型评审、是否自动返工（含最多轮数）、两项权重（机器 : 评审）、单价、当前模型。这些设置与工作台共用同一份配置，改哪边都生效。

**开跑前预估**：显示 `任务数 = 用例 × 风格 × 重复` 与预计花费（估算）。单价旁边注明**"参考价，以服务商官网为准，可自行修改"**。

**并发与叫停**：任务按设定并发逐个派发（不会一次性全发出去），进度条 + 「已完成 N / 计划 M」实时更新，明细表**边跑边填**；点「叫停」后不再派发新任务，正在跑的几条跑完即停。

**汇总看板**：平均总分、机器校验通过率、评审均分、**违禁词命中数**、**编造价格数**、总消耗 tokens、总耗时、预估花费，另附完成/失败、自动返工提升条数与评审失败条数。

**明细**：每行可展开——文案全文（含返工后的版本）、逐条校验结果（8 项，标出权重与硬伤）、评审四项分与点评、返工轨迹，以及**人工点赞 / 点踩 + 备注**。分数按区间上色（≥90 绿、≥75 橙、<75 红）。

## 三、历史与对比

- 每轮跑完自动保存：**当时的提示词原样快照** + 一个**短标识**（提示词哈希 + 日期时间，如 `pclu-0926T1445`），这是做对比的锚点；
- 选两次运行做 A/B：
  - **顶部**说明两次运行的提示词差在哪（角色设定 / 写作规范 / 素材模板 / 单件格式 / 范例 / 返工说明 / 评审提示词，逐项列出前后内容与字数变化）；
  - **中间**是指标涨跌表，带箭头与颜色（涨=绿↑、跌=红↓、持平=灰→；"违禁词命中数""编造价格数"这类越低越好，下降才算变好）；

## 四、拿评测结果反过来改提示词

汇总看板下面会自动给出**改进建议**（按未通过项统计），每条都带"为什么"和"可直接粘贴的规则原文"：

| 典型问题 | 建议 | 一键操作 |
| --- | --- | --- |
| 字数严重超标 | 软性描述（"篇幅控制在多少字"）模型基本不听，要写成硬要求："写完自己数一遍，超了就删，宁可少写一个卖点也不能超" | 写入写作规范 |
| 编造价格 | 加死约束："金额只能原样使用素材里给出的数字；素材没给的价格、折扣、销量、库存一律不许出现" | 写入写作规范 |
| 格式不稳 / 没有范例 | 要加一个范例；**范例本身必须满足所有约束**（例如它自己就得在字数区间内），否则范例会反过来把模型教坏 | 把本轮最高分文案设为范例 |
| 违禁词 / 话题标签 / 互动引导 / 表情数量 | 各自对应的硬性规范原文 | 写入写作规范 |

点完建议 → 保存配置 → **再跑同一批用例** → 在「历史与对比」里看指标涨跌，就能用数据证明这次改动确实变好了。

## 六、这一轮顺带修的问题

1. **默认规范升级为硬要求 + 补上合规范例**：原来默认规范第 3 条是软描述"篇幅控制在 60–320 字以内"，按第六段的结论把它改成硬要求"写完自己数一遍，超出上限就删…"，并给了一个**自己就满足全部约束**的范例（实测该范例机器校验 100 分）。改完默认值记得执行 `node scripts/gen-defaults.js` 重新生成服务端快照。
2. **模拟模型的"软规范不听"行为**：本地模拟模型现在会复现两类真实问题——规范只有软描述时照样写超字数、没有价格死约束时顺手编一个价；加上对应硬要求后自动恢复正常。这样不用真密钥也能演示"改提示词 → 分数上涨"的完整闭环。
3. **"必须提问结尾"的优先级**：模拟模型在同时要求"结尾提问"和"评论引导"时，原来会把互动语追加在问句之后，导致结尾不是问句；现在互动语放在问句之前，问句始终收尾。
4. **汇总看板字段取错**：把 `summarize` 的 `total` 误当成 `planned`，界面上出现过"计划 undefined"；已修正为「已完成 N 条 / 计划 M 条」。
