# 商品新增与编辑 · 使用说明

商品库现在可以维护了：新增与编辑都走弹窗，**弹窗右侧放一张实时预览卡片**，改哪一项立刻看到效果。

---

## 一、怎么打开

| 入口 | 位置 |
| --- | --- |
| 新增商品 | 商品库页「搜索、筛选与视图」区块右上角 **+ 新增商品** |
| 编辑商品 | 表格视图每行右侧的 **编辑**；卡片视图**点卡片本身**即可编辑（卡片结构保持不变，编辑入口挂在外层） |

---

## 二、字段与规则

| 字段 | 规则 | 不通过时的提示（写在字段下方） |
| --- | --- | --- |
| 编号 | 自动生成（取现有最大序号 +1），**不能与现有编号重复**；编辑时只读 | 编号 p1 已存在，请换一个（编号不能重复） |
| 名称 | 必填 | 名称必填，不能为空 |
| 售价 | 必须大于 0 | 售价必须是大于 0 的数字（当前：空） |
| 原价 | 必须大于 0，且**不低于售价** | 原价 199 低于售价 299，保存被拦住：请把原价调高到不低于售价（例如 ¥299） |
| 折扣率 | 由售价 / 原价**实时算出**（只读）；不合法时显示 — | — |
| 品类 | 可从已有品类下拉里选，也可直接输入新品类 | 品类不能为空：可以从已有品类里选，也可以直接输入新的 |
| 卖点 | 标签输入：回车添加、点 × 删除；**建议 2–4 个** | 至少要写 1 个卖点（建议 2–4 个）／卖点有 7 个，太多了，建议精简到 2–4 个 |
| 图标 | 36 个常用电商表情的快捷面板，**也允许手动输入** | 图标不能为空（可从快捷面板选，或手动输入一个 emoji） |
| 背景渐变 | 12 个预设配色点选，选中**即时反映到预览卡片** | — |
| 品牌 / SKU / 库存 / 销量 / 转化率 / 评分 | 选填，收在「更多字段」里，用于让预览卡片更完整 | — |

校验行为：刚打开弹窗时不弹错误；**点过一次保存后转为实时校验**，改对了错误立即消失。校验不通过时保存被拦住（弹窗不关闭、商品数量不变），并在底部给一句总体提示「还有 N 项没填对，请看字段下方的提示」。

## 三、实时预览卡片

弹窗右侧的预览卡片与工作台里的商品卡是**同一段渲染代码**（`HP.Products.cardHtml`），所以图标、渐变底色、品类徽章、卖点标签、价格与划线价、折扣角标全都所见即所得——改图标、点配色、输入价格、加删卖点，卡片立刻跟着变。

## 四、新增之后，工作台怎么找到它

1. **匹配商品（Step 3）能搜到**：搜索框匹配名称、卖点、品牌、SKU、品类（本轮把卖点也加进了搜索范围）；
2. **建议匹配商品（Step 2）会推荐它**：这轮把匹配算法从"命中预设关系就直接返回"改成**预设关系 + 语义兜底合并**——预设的热点-商品关系照旧，同时按热点关键词与品类语义对全库商品打分（含新商品），达标（≥62 分）的进推荐列表。所以运营新加的商品也有机会被热点带出来。

预览与推荐里的商品卡都来自同一段渲染，不会出现"后台看是一个样、工作台看是另一个样"。

## 五、本次实测结果

`node tests/ui-product-edit-tests.js` → **30 项通过 / 0 失败**（真实浏览器 + 真实服务端）

**验收 3 · 改图标或配色，预览卡片立即变化**

- 点表情面板 🧣 → 输入框与预览卡同时变成 🧣；手动输入 🧤 → 预览卡即时变成 🧤
- 点配色 mint → 预览卡背景从 `rgb(238, 240, 255)` 系变为 `rgb(230, 248, 242)` 系（mint）

**验收 2 · 原价低于售价 → 明确提示且保存被拦住**

- 售价 299 / 原价 199 → 字段下方提示「原价 199 低于售价 299，保存被拦住：请把原价调高到不低于售价（例如 ¥299）」，折扣率显示 —（不合法不显示折扣）
- 点保存：商品数量仍为 20、弹窗未关闭、底部提示「还有 1 项没填对」
- 改成 599 后：折扣率实时算出 50.1%，保存成功，商品数 20 → 21
- 顺带验证了名称未填 / 品类未填 / 卖点未填三条字段级提示都给出了具体原因

**验收 1 · 新增后工作台能搜到、也能被推荐**

- 新增「实测新品 加绒保暖防风外套」（编号自动生成 p21，与现有 20 个编号不重复），保存后服务端商品库 20 → 21 件
- 工作台「匹配商品」搜「实测新品」→ 命中 1 行；搜卖点里的「加绒保暖不透风」→ 同样命中
- 工作台 Step 2 推荐了 9 件，其中包含新增商品 p21（匹配度 78%）

**其它**

- 编辑现有商品：弹窗带出原有数据、编号只读且不会误报"编号已存在"、改名称预览卡立即更新、保存后列表显示新名称
- 测试收尾把服务端配置恢复为原始 20 件，脚本可重复运行
- 全流程无前端脚本报错

## 六、测试工具链的一次调整

本轮发现本机原来的 `playwright-core`（随全局 npm 包一起）已被清空，浏览器测试跑不起来。处理方式：

1. 把浏览器测试脚本改成**就近查找** playwright-core：优先工作区内 `.test-tools/node_modules`，其次 `node_modules`，最后才回退旧的全局路径；
2. 在工作区内安装（不写全局）：`npm install playwright-core --prefix .test-tools --no-save`。

`.test-tools/` 只是测试依赖，不进入交付内容；脚本找不到依赖时会明确提示这条安装命令。
