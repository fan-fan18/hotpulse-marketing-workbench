# 统一保存机制 · 使用说明

后台所有配置页共用同一套保存机制。这一套是运营"敢放心改东西"的前提：改了什么、存到哪了、坏了怎么退，都有明确反馈。

---

## 一、改动的可见性

| 状态 | 界面表现 |
| --- | --- |
| 已保存 | 底部操作栏写「已保存」，状态栏说明当前配置来自哪一级 |
| 有未保存改动 | 底部操作栏变暖色并写「有未保存的改动」；顶栏出现橙色「有未保存的改动」标记；「撤销未保存改动」按钮由禁用变为可点 |

底部操作栏固定贴在窗口底部，滚动时不消失。

## 二、保存

- **保存配置**（主操作）或快捷键 <kbd>Ctrl</kbd> + <kbd>S</kbd>；
- 保存后提示写明写回了哪一级：**「已保存到「服务端」」** 或 **「已保存到「本机浏览器」」**；
- 写服务端时会先备份上一版，提示里会带上备份文件名；
- 保存前会做一次校验，不合法的内容会被拦住并逐条列出原因（不会写坏配置）。

## 三、离开拦截

有未保存改动时，下面几种离开方式都会被拦一下：

1. **刷新 / 关闭标签页 / 关掉浏览器** → 浏览器原生提醒（"有未保存的配置改动，确定离开吗？"）；
2. **点左侧其它后台页面** → 弹出对话框，三个选择：
   - **留在本页**：什么都不做，改动与输入都保留；
   - **放弃改动并离开**：丢弃草稿、跳转过去；
   - **保存并离开**：先保存，成功后再跳转；
   - 对话框里还会列出「改动内容：提示词与模板（共 1 个区块）」，让人知道要丢的是什么。
3. **点顶栏「返回工作台」**、或在地址栏直接改 hash / 用浏览器前进后退 → 同样先问一下（地址栏会先退回当前页）。

## 四、导出与导入

- **导出配置**：把当前配置整体导出成 JSON 文件（文件名带时间戳，如 `hotpulse-config-20260920-2130.json`）。
- **导入配置**：导入前先校验——
  - 不是合法 JSON → 提示「不是合法的 JSON 文件：…」；
  - 顶层不是配置对象、或没有任何可识别配置项 → 提示「文件里没有可识别的配置项（应该是从本后台导出的配置文件）」；
  - 内容不合法（例如商品为空）→ 逐条列出原因。
  - **任何情况下原配置都不受影响**，对话框里明确写着「原有配置没有受到任何影响，修好文件后可以再导入」。
- 导入成功后弹窗给出摘要（商品 N 件 / 创作风格 N 个 / 语调 N 个 / 来源 N 个），并明确"还没有写回服务端"，可选择 **立即保存** 或 **稍后保存**。
- 导出的文件可以原样再导回来（实测配置内容不变）。

## 五、分区块恢复默认

不是只有一个全局重置：

- **每个配置区块的右上角**都有「恢复本区块默认」，只把这一块（例如「提示词与模板」）还原成默认值，其它区块不受影响；
- **底部操作栏的「恢复本页默认」**把当前页面涉及的所有区块一起还原（例如创作风格 + 语调预设）；
- 恢复后是"未保存"状态，确认无误再点保存；不想留了就点「撤销未保存改动」。

## 六、服务端一侧的三道保险

| 保险 | 行为 |
| --- | --- |
| **写入前备份** | 每次写入前把上一版复制到 `data/backups/config-<时间戳>.json`，保留最近 10 份，方便回滚 |
| **读取时补默认值** | 读取时逐区块与默认值对比，缺失的自动补上；页面顶部会提示「检测到服务端配置缺少 N 个区块（xxx、yyy），已自动用内置默认值补齐，页面可正常工作」 |
| **空值防线** | 商品列表为空、创作风格删到零、语调删到零、角色设定 / 素材模板 / 单件格式为空 → 一律拒绝写入，原配置保持不变 |

## 七、本次实测结果

`node tests/ui-save-tests.js` → **29 项通过 / 0 失败**（真实浏览器 + 真实服务端）

**验收 1 · 改了不保存直接刷新会被提醒**

- 改一行角色设定后：状态栏变「有未保存的改动」，顶栏橙色标记出现
- 刷新：弹出 `beforeunload` 对话框；选择「留下」后页面没跳走，输入框内容仍在
- 保存后再刷新：不再拦截（对话框为 null）

**验收 2 · 服务端配置被删掉一段，重开后台自动补齐**

- 直接编辑 `data/config.json` 删掉 `tones` 与 `model` 两段
- 服务端读取返回 `filled: ["tones","model"]`
- 重新打开后台：顶部提示「检测到服务端配置缺少 2 个区块（语调预设、模型与接入），已自动用内置默认值补齐，页面可正常工作」
- 语调重新出现 4 个；模型页 4 个区块正常渲染、模型名为默认的 `gpt-4o-mini`；全程无脚本报错

**验收 3 · 导入格式错误的文件**

| 文件 | 提示 | 配置是否受影响 |
| --- | --- | --- |
| `{ 这不是合法的 JSON` | 导入失败：文件格式有问题 · 不是合法的 JSON 文件：… | 未受影响 |
| `{"hello":"world","foo":1}` | 导入失败：文件格式有问题 · 没有可识别的配置项 | 未受影响 |

两次导入坏文件后比对服务端配置内容，与本轮开始时完全一致。

**其它**

- Ctrl+S 保存：提示「已保存到「服务端」」，服务端 `prompt.role` 确实变成新值
- 离开拦截：提示含「留在本页 / 放弃改动并离开 / 保存并离开」三个选择，并列出「改动内容：提示词与模板（共 1 个区块）」；选留在本页 → 地址与输入都保留；选放弃 → 跳转成功且草稿恢复为已保存内容
- 分区块恢复：只改 role 时恢复「提示词与模板」→ role 还原，而同时改过的风格名「被改过的风格名」不受影响；底部「恢复本页默认」把风格与语调一起还原
- 导出 → 再导入：导出文件 12513 字节，导回后配置内容与导出前一致

## 八、这一轮的两个小改进

1. **导入成功从 toast 升级为弹窗**：现在会给出导入摘要，并提供「立即保存 / 稍后保存」，避免"导进去了但忘了存"。
2. **补齐提示移到页面顶部**：以前只在「配置总览」里能看到自动补齐信息，现在任何页面打开都会先看到一条蓝色提示，说明补了哪些区块；保存一次后该提示消失。
