# 提示词与模板页 · 使用说明

后台的「提示词与模板」页，把原本写死在代码里的模型指令搬到了配置里。运营改完保存，**工作台下一次生成立刻生效**，不需要改代码、不需要重新部署。

入口：`admin.html#/prompts`（或点开后台后选左侧「提示词与模板」）。

---

## 一、可编辑的三块内容

| 区块 | 作用 | 影响范围 |
| --- | --- | --- |
| **角色设定与写作规范** | 模型的身份设定 + 逐条写作规范。规范可以增删改、上下移动调整优先级 | 每次调用都会作为「系统提示词」的一部分发给模型 |
| **素材模板** | 每次调用时用来拼装素材的骨架，运行时内容用占位符表示 | 决定模型看到的素材长什么样 |
| **单件商品在素材里的呈现格式** | 商品清单里「每一件」长什么样 | 只作用于单件；`{{商品清单}}` 会把它们逐件渲染后拼起来 |

规范里同样可以写占位符。例如把第 3 条写成：

```
篇幅控制在 {{字数下限}}–{{字数上限}} 字以内，写完自己数一遍，超了就删。
```

保存后编译时会自动填成实际数值（默认 `60–320`）。

## 二、占位符清单

点页面里的**「查看完整清单与说明」**可以打开弹窗，逐条查看并一键插入。完整清单如下：

### 热点素材

| 占位符 | 代表什么 |
| --- | --- |
| `{{热点标题}}` | 当前选中热点的新闻标题 |
| `{{热点摘要}}` | 热点的摘要正文 |
| `{{来源}}` | 热点来源媒体 / 平台名称 |
| `{{热度值}}` | 热点热度分（0–1000） |
| `{{热点关键词}}` | 顿号分隔的关键词，如「冷空气、一夜入秋」 |
| `{{热度趋势}}` | 近 7 个采样点的热度走势，如 `22→30→…→96` |
| `{{话题标签}}` | 本次可用话题标签，如「#冷空气来了# #一夜入秋#」 |
| `{{当前日期}}` | 生成时的日期 |

### 商品素材

| 占位符 | 代表什么 |
| --- | --- |
| `{{商品清单}}` | **嵌套占位符**：每件商品按「单件格式」渲染后逐行拼接 |
| `{{商品数量}}` | 本次绑定的商品件数 |
| `{{主推商品}}` | 主推商品名称（绑定列表第一件） |

| `{{卖点列表}}` | 主推商品卖点，顿号分隔 |
| `{{可用金额}}` | 素材里允许出现的全部金额（防止模型编造价格） |

### 本次要求

| 占位符 | 代表什么 |
| --- | --- |
| `{{语调}}` | 本次主打语调（来自后台的语调预设） |
| `{{创作风格}}` / `{{风格要求}}` | 这次生成使用的创作风格名称与要求原文 |
| `{{字数下限}}` / `{{字数上限}}` / `{{话题标签上限}}` | 来自后台阈值配置 |
| `{{表情强度}}` | 不使用 / 适中 / 丰富 |
| `{{附加要求}}` | 工作台里临时填写的附加要求，没有则为空 |

### 单件商品格式（只作用于 `{{商品清单}}` 内部）

| 占位符 | 代表什么 |
| --- | --- |
| `{{序号}}` | 在清单中的序号，从 1 开始 |
| `{{商品名称}}` / `{{品牌}}` / `{{编号}}` / `{{图标}}` / `{{品类}}` | 商品基础信息 |
| `{{售价}}` / `{{原价}}` / `{{节省金额}}` / `{{商品折扣率}}` | 价格相关字段 |
| `{{主推标记}}` | 主推商品显示「（主推）」，其余为空 |
| `{{卖点列表}}` | 该商品的卖点，顿号分隔 |
| `{{商品说明}}` | 一句话说明，如「近 30 天卖出 1.2 万 件、转化率 6.4%」 |

## 三、两条关键规则

**1. 点一下就能插到光标位置。**
先用鼠标点进要编辑的输入框（把光标放到目标位置），再点占位符面板里的条目，占位符会插入到光标处，原内容不受影响；连续点击会依次往后排。

**2. 不认识的占位符原样保留，不会被替换成空白。**
写错时预览里会**原样显示** `{{写错的占位符}}` 并标红，下面给出「发现 N 个不认识的占位符」的提示。这样运营一眼就能看出是哪里写错了，而不是看到一段莫名变短的内容。

## 四、它是怎么串到工作台的

```
后台「提示词与模板」
        ↓ 保存（服务端 → 本机浏览器 → 内置默认值，三级）
工作台 Step 4 点「生成文案」
        ↓ 编译：角色设定 + 写作规范 → 规范块
        ↓       素材模板（含 {{商品清单}} 嵌套渲染）→ 素材块
        ↓ 每个创作风格独立调用一次模型
   候选版本 ×N（每个风格一版）
```

因为工作台读的就是后台那同一份配置，所以「改规范 → 保存 → 回工作台生成」是即时生效的，不需要重启、也不需要重新构建。

## 五、试运行（用当前模板真调一次）

实时预览解决了"看不见"，试运行解决"不敢发"。点「试运行一次」会用**当前编辑中的模板**（不用先保存）真发一次请求，返回四件事：生成结果、耗时、消耗量、这次用的是哪个模型和哪种接入方式。

三种接入方式都能跑：

| 接入方式 | 请求路径 | 密钥放哪 |
| --- | --- | --- |
| 本地模拟 | 不发网络请求，本地模拟输出 | 不需要 |
| 本地服务中转 | 浏览器 → 本机服务端 `/api/llm` → 服务商 | 服务端环境变量 `HOTPULSE_API_KEY`，**浏览器不接触密钥** |
| 浏览器直连 | 浏览器 → 服务商 `/chat/completions` | 本机浏览器；可能被服务商的跨域策略拦截 |

调用失败时，页面给的是**人话原因**，不是原始报错：

| 服务商返回 | 页面提示 |
| --- | --- |
| 401 / `invalid_api_key` | 密钥无效，请检查密钥是否正确、是否过期 |
| 402 / `insufficient_quota` | 账户余额不足或额度已用完 |
| 404 / `model_not_found` | 模型名不存在，请核对模型名称 |
| 429 / `rate_limit_exceeded` | 请求被限流，请降低并发或稍后重试 |
| 超时 / 连不上 | 请求超时：接口地址可能不对，或网络不稳定 |

原始响应被收进折叠的「技术细节（可选）」里，只在排查时展开。

另外两条约束：

- 本地模拟模式下，结果区上方会有醒目提示：**现在是模拟输出，不代表真实模型效果**；
- 无论成功失败，结果只用于调试，**不写回工作台**——工作台里的候选文案不会因为一次试运行而变化。

## 六、本次实测结果

**内核实测** `node tests/prompt-tests.js`：**22 项通过 / 0 失败**

- 未知占位符原样保留（`标题：冷空气来袭；未知：{{我写错了}}`），并被记录下来用于提示
- 占位符内部带空格也能识别（`{{ 热点标题 }}`）
- 嵌套渲染：3 件商品 → 渲染成 3 行，每行都按单件格式带上序号与真实价格，无未渲染残留
- 改成自定义单件格式后立即按新格式渲染（`【1】🧥三合一防风冲锋衣 … / ¥299→¥599 / 加绒内胆可拆、…`）
- 编译结果分两块：规范块 139 字、素材块 267 字；规范里的 `{{字数下限}}–{{字数上限}}` 被填成 `60–320`
- 改一句规范，规范块立即从 139 字变为 163 字
- 新增「结尾必须以提问结尾」→ 输出确实以问句收尾；「不超过 120 字」→ 输出压到 107 字；「不要出现感叹号」→ 0 个感叹号；「不要使用 emoji」→ 0 个表情
- 4 个创作风格 → 4 种互不相同、可区分的候选版本

**浏览器实测（模板编辑与生效链路）** `node tests/ui-prompt-tests.js`：**16 项通过 / 0 失败**

- 验收 2：光标置于第 6 个字符 → 占位符插入位置 = 6，内容长度 47 → 55（正好 +8 字符），原内容无破坏；连续插入接着往后排；完整清单弹窗 36 条
- 验收 3：写入 `{{这个占位符不存在}}` → 预览原样显示该文本、标红 1 处、并提示「发现 1 个不认识的占位符」
- 验收 1：基线（未加新规范）4 个版本都不以提问结尾 → 保存新规范「结尾必须以提问结尾」→ 回工作台重新生成，4 个版本**全部以问句收尾**；候选版本数 = 选中的创作风格数（4 → 4）
- 再加一条「不要使用 emoji」→ 工作台输出表情符号总数从 4 降到 **0**
- 全程无前端脚本报错；测试结束后自动清理回默认 3 条规范

> 说明：以上验证跑的是「本地模拟」接入方式。模拟模型会读同一份提示词并遵守其中的可判定约束（字数、违禁词、emoji、结尾形式等），用于验证链路与模板改动是否生效；换成真实模型（后台「模型与接入」页配置服务商与密钥）后，同一份提示词会原样发给真实模型。
