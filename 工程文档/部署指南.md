# 部署指南（HotPulse 热点营销工作台）

> 本文只讲"怎么把它跑起来、放到哪里跑、跑完怎么自检"。
> 技术前提：**零依赖**（只用 Node 内置模块）、**无构建步骤**（不需要 npm install、不需要打包）。
> 唯一要求：机器上有 **Node 18 或更高版本**（`node -v` 能看到版本号即可；实测环境是 Node v24.14.0）。

---

## 一、三种部署形态，按需要选一种

| 形态 | 怎么打开 | 配置存在哪 | 抓取/试运行 | 适合谁 |
| --- | --- | --- | --- | --- |
| **本地演示** | 直接双击 `index.html` / `admin.html` | 本机浏览器 localStorage | 不真抓、试运行是模拟输出 | 给同事看界面、讲流程 |
| **本机服务端**（推荐） | `node server/server.js` 后访问 `http://localhost:8787` | 服务端 `data/config.json` | 真抓 RSS/JSON 源、真调模型 | 日常运营、自己办公电脑 |
| **局域网 / 服务器** | 服务端跑在固定机器上，别人用 IP 或域名访问 | 服务端 `data/config.json` | 同上，全组共用一份配置 | 小组共用、对外演示 |

顶栏徽章会如实告诉用户当前是哪一级：**服务端** / **本机浏览器** / **内置默认值**。
同一份前端代码，不需要为不同形态改任何东西。

---

## 二、本机服务端：三步

1. 双击项目根目录的 **`启动服务.bat`**
   （脚本会检查 Node、打印端口、2 秒后自动打开工作台；关掉窗口或按 Ctrl+C 即停止）
2. 工作台：`http://localhost:8787/index.html`
3. 后台：`http://localhost:8787/admin.html`

不想用脚本、或者脚本被安全策略拦了，就用命令行：

```bat
cd /d "D:\你的目录\热点营销工作台"        :: 换成你实际的项目目录
node server/server.js            :: 默认 8787
node server/server.js 8788       :: 换端口（第一个参数就是端口）
```

启动成功会看到（实测输出）：

```
HotPulse 服务端已启动  2026/10/16 19:15:04
  监听地址：0.0.0.0:8799
  工作台：http://localhost:8799/index.html
  后台  ：http://localhost:8799/admin.html
  局域网：http://192.168.3.106:8799/index.html
  配置文件：...\热点营销工作台\data\config.json
  备份目录：...\热点营销工作台\data\backups
  定时抓取：已开启，启动 3 秒后先跑一次，之后每 10 分钟一次
  静态访问已收口：data/ server/ tests/ scripts/ work/ outputs/ 不对外开放
```

可选环境变量：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `PORT` | 端口（也可用第一个命令行参数，参数优先） | `8787` |
| `HOST` | 监听地址；`127.0.0.1` 表示只允许本机访问 | `0.0.0.0`（同局域网可访问） |
| `HOTPULSE_API_KEY` | 服务端持有的模型密钥，浏览器完全不接触密钥 | 空 |

### 2.4 热点池与定时抓取（`data/news.json`）

服务端启动 3 秒后会先抓一次，之后每 `fetch.intervalMin` 分钟抓一次（默认 10）。
抓取结果落在 **`data/news.json`**（与 `config.json` 分开存）：

```json
{
  "version": 1,
  "updatedAt": "2026-10-23T07:25:11.000Z",
  "items": [
    { "id": "sn_xxx", "title": "…", "source": "中国天气网", "sources": ["中国天气网"],
      "sourceIds": ["src_weather"], "heat": 812, "seenCount": 3,
      "firstSeen": "…", "lastSeen": "…", "history": [{ "t": "…", "heat": 812 }] }
  ],
  "runs": [{ "at": "…", "ms": 724, "added": 3, "merged": 0, "okSources": 5, "failedSources": 2, "sources": [] }]
}
```

- **原子写**：先写 `news.json.tmp` 再 rename，写一半断电不会留下坏文件。
- **不需要备份**：热点池是可再生的缓存（抓一次就回来了）；要备份就备份 `config.json`。
- **想重置**：停服务 → 删掉 `data/news.json` → 起服务，3 秒后重新抓一次。
- **不想自动抓**：后台「抓取来源 → 定时抓取与热点池」关掉开关（或把 `fetch.enabled` 设为 false），
  工作台右上角「一键抓取」仍可手动触发。
- 浏览器直接访问 `/data/news.json` 是 **403**，不会把池子暴露出去。

## 三、局域网 / 服务器部署

### 3.1 同一局域网共用

在一台常开的机器上启动服务端，其他人用启动日志里的「局域网」地址访问即可，
例如 `http://192.168.3.106:8787/index.html`。
注意：**全组共用一份 `data/config.json`**，谁保存都写这同一份（写入前会自动备份上一版）。

### 3.2 Linux 服务器（systemd 常驻）

```ini
# /etc/systemd/system/hotpulse.service
[Unit]
Description=HotPulse 热点营销工作台
After=network.target

[Service]
WorkingDirectory=/opt/hotpulse
Environment=PORT=8787
Environment=HOST=127.0.0.1
# 密钥放服务端环境变量，不要写进配置文件、不要发到浏览器
Environment=HOTPULSE_API_KEY=你的密钥
ExecStart=/usr/bin/node /opt/hotpulse/server/server.js
Restart=always
User=hotpulse

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now hotpulse
curl -s http://127.0.0.1:8787/api/health     # 应返回 {"ok":true,...}
```

### 3.3 Nginx 反向代理 + HTTPS（示例）

```nginx
server {
  listen 443 ssl;
  server_name hotpulse.example.com;
  ssl_certificate     /etc/ssl/hotpulse.crt;
  ssl_certificate_key /etc/ssl/hotpulse.key;

  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
```

用了反代就不要再让服务端直接暴露在公网：把 `HOST` 设成 `127.0.0.1`，由 Nginx 统一收口。

## 五、静态资源收口（这次部署新加的防线）

原来的静态服务会把**整个项目根目录**对外暴露，实测 `GET /data/config.json` 返回 **200 / 16181 字节**——
而 `data/config.json` 里就有 `model.apiKey` 字段。也就是说：一旦把服务端放到公网，任何人访问
`/data/config.json` 就能把密钥读走。`/server/server.js`（服务端源码）同样可以整份下载。

现在的规则（`server/server.js` 的 `staticBlocked()`）：

- 目录黑名单：`data` `server` `tests` `scripts` `work` `outputs` `node_modules` → 403
- 隐藏文件/目录（`.` 开头，含 `.test-tools`）→ 403
- 路径里出现 `..`（含 `%2e%2e` 解码后）→ 403
- 其余按原样静态返回；`工程文档/` 仍可访问（便于在浏览器里查文档）

收口前后实测对比：

| 请求 | 收口前 | 收口后 |
| --- | --- | --- |
| `GET /data/config.json` | 200（16181 B，含密钥字段） | **403** |
| `GET /server/server.js` | 200（14959 B） | **403** |
| `GET /tests/ui-smoke.js` | 200 | **403** |
| `GET /%2e%2e/data/config.json` | 200 | **403** |
| `GET /index.html` | 200 | 200（19984 B） |
| `GET /assets/css/styles.css` | 200 | 200（35261 B） |

## 六、数据、备份与回滚

- 配置文件：`data/config.json`（唯一一份真实配置，前端三级读取的最高级）
- 备份目录：`data/backups/`，每次写入前复制上一版，**只保留最近 10 份**
- 回滚：把要回滚的那份备份复制成 `data/config.json` 覆盖即可（服务端会立刻按新内容生效）
- 误删整段不用慌：读取时会自动补默认值，并在后台顶部提示"补了哪些区块"
- 换机器/迁移：用后台的**导出配置**按钮拿一份 JSON，在新机器上**导入**即可；导入会先校验格式

## 七、公网部署前必须补的（当前是原型，别直接挂公网）

| 缺口 | 现状 | 上公网前要做 |
| --- | --- | --- |
| 访问控制 | **没有登录**，谁打开链接谁就能改配置 | 加鉴权（反向代理 Basic Auth 或应用层登录 + 角色权限） |
| 密钥管理 | 支持服务端环境变量，但后台也允许把密钥存进配置 | 强制走服务端环境变量；后台密钥框只读或隐藏 |
| CORS | 服务端固定回 `Access-Control-Allow-Origin: *` | 收紧到实际域名 |
| 传输加密 | 明文 HTTP | Nginx 上 HTTPS，`HOST` 只监听 127.0.0.1 |
| 并发写 | 单文件直写，无锁 | 多实例/多人同时写要换数据库或加锁 |
| 审计 | 只有备份，没有操作日志 | 记录"谁在什么时候改了什么" |
| 发布通道 | Step 5 的"一键发送"是模拟 | 接微博开放平台写权限、token 续期、幂等与重试 |

## 八、常见问题

**端口被占用**：启动时会提示 `端口 8787 已被占用：换一个端口启动，例如 node server/server.js 8788`。
换端口后记得用新端口的地址打开页面。

**徽章显示"本机浏览器"，但服务端明明启动了**：说明页面不是从 `http://` 打开的（双击文件打开的就是这种情况），
或者端口不对。用启动日志里那条 `http://localhost:端口/index.html` 重新打开。

**局域网里别人打不开**：确认 `HOST` 不是 `127.0.0.1`；确认 Windows 防火墙放行了该端口。

**模型试运行报"密钥无效"**：后台 → 模型与接入页，检查接入方式选的是「本地服务中转」还是「浏览器直连」。
走服务端中转时，密钥优先取服务端环境变量 `HOTPULSE_API_KEY`。

**选了「本地服务中转」却发不出去**：这个模式必须有服务端。直接双击文件打开（`file://`）时，
接入方式卡片上会出现黄色提示「⚠ 没有检测到服务端……」，调用也会直接告诉你要先启动服务端，
不会再报成"网络不可达或接口地址不对"。启动服务端并从 `http://localhost:8787` 打开即可。

**页面显示"演示模式 · 未连接服务端"**：这是工作台顶部的状态灯，代表当前没有连上服务端，
此时不会真的去抓外部站点，列表只显示已启用来源里已有的条目。启动服务端并从 `http://` 打开即可消除。
