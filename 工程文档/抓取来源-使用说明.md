# 抓取来源页 · 使用说明

抓取来源不再写死在代码里：内置平台热榜可以启停，运营也可以添加自己的新闻订阅源。**停用某个来源后，工作台的热点列表里就不会再出现它的新闻**——这一条是真的生效，不是界面上的开关摆设。

入口：`admin.html#/sources`

---

## 一、五个区块

### 1. 来源列表

内置 8 个平台/媒体来源：中国天气网、微博热搜榜、新浪科技、携程研究院、小红书趋势、量子位、人民日报健康、经济观察报；另外带一个"行业媒体订阅（示例）"的自定义源作参考。

| 能做什么 | 说明 |
| --- | --- |
| 启用 / 停用 | 每行最左侧开关；停用并保存后，工作台不再抓取它 |
| 改名称 / 地址 / 备注 | 直接改，各自的字段独立输入 |
| 删除 | **只有自定义来源能删**（内置来源显示"不可删除"，但可以停用），删除前二次确认 |
| 已抓条目 | 显示该来源当前配置里存了多少条抓取结果 |

### 2. 添加新闻订阅源

填名称 + 地址（RSS / Atom 订阅地址，或返回 JSON 列表的接口地址）。**地址格式会先校验**：不是 `http://` 或 `https://` 开头时，在输入框下方直接提示

```
地址格式不对：必须以 http:// 或 https:// 开头（当前：htp:/bad url）
```

并且不会把这条来源加进去。

### 3. 测试全部来源

点「测试全部来源」，对**每个**来源真发一次 GET 请求（含停用中的，方便决定要不要重新启用），逐个给出：

| 列 | 内容 |
| --- | --- |
| 结果 | 成功 / 失败 |
| 条数 | 解析出的条目数（RSS / Atom 条目、JSON 列表长度、或页面链接数） |
| 耗时 | 毫秒 |
| 说明 | 成功写"解析出 N 条订阅条目"；失败写人话原因 |
| 抓到条目 | 能解析出条目的来源显示条数 |

失败原因都是人话，例如：

- `地址格式不对：必须以 http:// 或 https:// 开头`
- `域名解析失败：地址可能不存在或写错了`
- `对方拒绝连接（端口未开放或被防火墙拦截）`
- `连接超时：对方没有在 6 秒内响应`
- `对方返回 HTTP 403（拒绝访问）`
- `HTTPS 证书校验失败`

**一个来源失败不影响其它来源**，每个来源独立测试、独立显示结果。

抓取走哪条路：

- 有本地服务端时走服务端（`POST /api/sources/test`），不受浏览器跨域限制；
- 没有服务端时退化为浏览器直连，页面会提示"公开站点通常会被跨域策略拦截"，这属于预期现象。

**抓到的条目怎么进工作台**：测试成功的来源，其条目会自动写入编辑区（每个来源最多保留 10 条），来源列表的"已抓条目"列会显示条数；点底部「保存配置」后，工作台的热点列表里就能看到来自它的新闻（来源名显示为该订阅源名称，可以正常被选中、匹配商品、生成文案）。

### 4. 合规提示

页面里用醒目样式写清了：

> **公开热榜接口只适合原型演示。** 正式上线应改用官方开放平台或商业舆情服务，并遵守对方的爬虫协议与服务条款。
> 具体要求：不绕过反爬机制、不伪造身份高频抓取、不抓取需要登录或明确付费的内容；不抓取用户隐私数据；控制抓取频率并保留来源标注与原文链接；商用前确认转载授权，涉及新闻作品时尤其注意版权。

同时注明：本页的"测试全部来源"只对填写的地址发一次 GET 请求，用于验证连通性，不做批量或定时抓取。

### 5. 风险识别规则说明

两份可以直接维护的清单（可增删条目）：

| 禁止借势（命中即不建议参与） | 需人工判断（谨慎参与） |
| --- | --- |
| 灾难事故（伤亡、失联、事故原因未明） | 重大体育赛事结果（胜负情绪易引发对立） |
| 公共安全事件（案件侦办中、官方通报前） | 娱乐明星争议（存在反转风险） |
| 医疗与药品功效宣称 | 节庆与纪念日（需注意口径） |
| 涉政、涉宗教、涉民族敏感话题 | 价格与促销政策（以官方活动页为准） |
| 负面舆论与维权争议 | |

## 二、和工作台的联动关系

### 工作台侧的真实行为（含"为什么抓不到热点"）

工作台的新闻列表 = **启用中的来源** 底下的条目：

- 内置 8 条演示新闻各自挂在 8 个内置来源上（`sourceId`），来源一停用，它的新闻就从列表消失；
- 自定义订阅源显示的，是它**已经被抓到的条目**（存在配置里，换页面/刷新都还在）。

所以列表为空只有三种可能，页面上现在都会直接说清楚：

| 情况 | 页面表现 | 怎么办 |
| --- | --- | --- |
| 所有来源都停用了 | 空列表 +「当前没有启用中的抓取来源」+ 按钮「恢复并启用内置来源」 | 点按钮，或在后台「抓取来源」里勾回启用 |
| 启用的来源底下一共 0 条条目（例如只启用了两个还没抓成功的自定义订阅源） | 空列表 +「你启用的 N 个来源，底下一共 0 条条目」+ 逐个列出每个来源的条数 | 服务端模式下点「一键抓取」真去抓；或先恢复内置来源 |
| 有来源也有条目，只是筛选太窄 | 空列表 +「没有匹配的热点」 | 调整关键词/类目/时间范围 |

两种运行模式的区别（顶部状态灯会写明当前是哪种）：

| 打开方式 | 状态灯 | 「一键抓取」的真实行为 |
| --- | --- | --- |
| 双击 `index.html`（file://） | 演示模式 · 未连接服务端 | **不真抓**，只重新渲染已有条目，并明确提示"演示模式：没有真的抓取"。因为浏览器跨域会拦掉外部站点 |
| 启动 `node server/server.js` 后用 `http://localhost:8787/index.html` | 抓取服务在线 | **真的抓**：服务端逐个访问启用中的来源，解析到的条目写回配置并出现在列表；提示里给出"成功 N/M 个来源、写入 K 条条目" |

> 公开热榜（微博热搜榜、百度热搜榜这类）多为前端渲染 + 反爬，服务端也解析不出标题；要拿到稳定条目，建议用 **RSS / JSON 订阅源**，正式上线再用官方开放平台或商业舆情服务。

```
后台「抓取来源」
   ├─ 启用/停用 ──→ 工作台 Step 1 的热点列表只包含启用来源的新闻
   ├─ 自定义订阅源 + 测试抓到的条目 ──→ 保存后成为工作台里的新闻（来源显示为订阅源名称）
   └─ 默认值变更后需执行 node scripts/gen-defaults.js 重新生成服务端默认值快照
```

工作台侧对应改动：

- 每条内置新闻都带上了 `sourceId`，与来源一一对应；
- 热点列表 = 启用来源的内置新闻 + 启用订阅源抓到的条目；
- 首页统计卡片的"覆盖 N 个源"变为动态显示启用来源数；
- 「一键抓取」会先同步一次配置，所以后台刚启停的来源、刚抓到的条目立刻生效；
- 所有来源都被停用时，工作台给出明确空状态："当前没有启用中的抓取来源，请到后台「抓取来源」里启用至少一个来源"。

## 三、本次实测结果

`node tests/ui-sources-tests.js` → **27 项通过 / 0 失败**（真实浏览器 + 真实服务端 + 本地测试订阅源）

**页面与文案**：五个区块齐全；列出全部 9 个来源（内置 8 + 自定义 1）；合规提示包含"只适合原型演示 / 官方开放平台或商业舆情服务 / 遵守爬虫协议与服务条款"；风险规则禁止借势 5 条、需人工判断 4 条。

**地址格式校验**：填 `htp:/bad url` → 字段下方提示"必须以 http:// 或 https:// 开头"；来源数量没变。

**测试全部来源**：11 个来源 → 成功 9 个、失败 2 个、解析出条目 27 条；订阅源「实测订阅源X」一行显示"成功 / 3 条 / 3 ms / 解析出 3 条订阅条目"；不存在的地址显示"失败 / 0 条 / 47 ms / 域名解析失败：地址可能不存在或写错了"；**其它来源仍然是成功**。

**验收 2（订阅源进工作台）**：保存后服务端配置里该来源带 3 条条目；工作台热点列表里出现 3 条来自「实测订阅源X」的新闻，标题确实是抓到的原文标题（如"订阅源测试：办公室养生潮带动热饮器具"）。

**验收 1（停用来源）**：停用「中国天气网」并保存 → 工作台热点列表里不再有该来源的新闻，"冷空气来袭"那条也消失了；其它来源（新浪科技、订阅源）不受影响；再点「一键抓取」仍然不会出现被停用的来源。

**自定义可删 / 内置不可删**：删除按钮数量 = 自定义来源数量；删除自定义来源需二次确认，删除后数量正确减少。

## 四、注意

改了内置默认值（来源清单、风险规则）之后，记得执行一次 `node scripts/gen-defaults.js` —— 服务端读取配置时会用这份快照补齐缺失内容，快照过期会导致新建的配置缺少新来源。
