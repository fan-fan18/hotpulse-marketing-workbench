# 接口预留与接入说明（LLM / Coze / 真实数据源）

本原型已经把「会变的部分」和「不变的部分」隔离开了，接入真实服务时改动面很小。

---

## 1. 模块边界

| 模块 | 文件 | 职责 | 接真实服务时的动作 |
| --- | --- | --- | --- |
| 数据层 | `assets/js/data.js` | 新闻列表、商品库、热点-商品匹配关系、文案模板、Emoji 库 | 替换为后端接口返回（结构保持一致即可） |
| 业务层 | `assets/js/app.js` | 步骤状态机、筛选、匹配打分、文案生成、合规校验、发布模拟 | 把 `simulateFetch()` / `generateAll()` / `publish()` 内部换成真实请求 |
| 视图层 | `index.html` + `assets/css/styles.css` | 布局、卡片、表格、微博卡片预览 | 基本无需改动 |

全局唯一的数据出口是 `window.MOCK`，把它的四个字段换成后端响应即可：

```js
window.MOCK = { NEWS, PRODUCTS, MATCH_MAP, COPY_TEMPLATES, EMOJI_LIB, CTAS };
```

## 2. 数据契约

### 2.1 热点新闻 `NEWS[]`

```json
{
  "id": "n1", "cat": "民生天气", "source": "中国天气网",
  "time": "14:32", "minutesAgo": 18,
  "title": "冷空气来袭！北方多地气温骤降 10℃，一夜入秋",
  "summary": "…", "heat": 986, "growth": 42,
  "keywords": ["冷空气", "一夜入秋"], "tags": ["热搜第 3"],
  "topics": ["#冷空气来了#", "#一夜入秋#"],
  "spark": [22, 30, 38, 41, 58, 79, 96]
}
```

### 2.2 商品 `PRODUCTS[]`

```json
{
  "id": "p1", "name": "三合一防风冲锋衣 加绒可拆内胆", "brand": "拓行 TROXON",
  "cat": "服饰鞋包", "price": 299, "marketPrice": 599,
  "stock": 1280, "rating": 4.9, "sales30d": 12480,
  "conversion": 6.4, "gmv30d": 373.2, "emoji": "🧥", "sku": "TX-A219",
  "points": ["加绒内胆可拆", "防风防泼水面料", "显瘦直筒版型"]
}
```

> `points` 建议保持 **不带逗号的短语**（≤12 字），因为它会被直接拼进微博文案的语气流里，带逗号会让句子读起来断裂。

### 2.3 匹配关系 `MATCH_MAP`

```json
{
  "n1": [
    { "pid": "p1", "score": 96, "reason": "「断崖式降温」下加绒外套搜索量 +312%，<b>客单价 299 元决策周期最短</b>…" }
  ]
}
```

`reason` 支持 HTML（用于加粗关键结论）。若某条热点没有预设匹配，`app.js` 的 `matchesFor()` 会自动走**关键词+类目语义兜底打分**，因此新增热点不会出现空白页。

## 3. 接入真实 LLM（例如通义 / DeepSeek / GPT）

替换 `generateAll()` 中的 `setTimeout(...)` 段，改为真实请求。建议契约：

**请求**

```http
POST /api/llm/generate
Content-Type: application/json

{
  "news":    { "title": "…", "keywords": ["…"], "topics": ["#…#"] },
  "product": { "name": "…", "price": 299, "marketPrice": 599, "points": ["…", "…"] },
  "config":  { "style": "种草安利", "emojiLevel": 1, "tags": ["#冷空气来了#"], "points": ["加绒内胆可拆"], "extra": "" },
  "count": 3
}
```

**响应**

```json
{
  "versions": [
    { "label": "版本 A · 稳妥主推版", "style": "种草安利", "text": "【冷空气来袭】🥶 …#冷空气来了# #一夜入秋#" }
  ],
  "usage": { "model": "qwen-max", "latencyMs": 1420 }
}
```

前端只需把返回的 `versions` 直接赋给 `state.copy.versions`（元素结构为 `{ id, label, style, text, tune }`），其余渲染、复制、微调、送审逻辑全部复用。

**提示词骨架（可直接放进 Coze / Dify 的工作流）**

```
你是资深微博电商内容运营。基于以下信息写 {count} 个不同角度的微博营销文案。
热点：{news.title}｜关键词：{keywords}
主推商品：{product.name}｜价格：{price}（原价 {anchor}）｜核心卖点：{points}
风格：{style}｜Emoji 强度：{emojiLevel}｜必须包含话题：{tags}
硬性要求：
1) 纯文本，不用 Markdown，不用标题；
2) 开头 15 字内点明热点，正文自然带出商品与卖点；
3) 必须包含 1–3 个 #话题#；
4) 结尾必须有一句互动引导；
5) 不得使用「最」「第一」「100%」「永久」「根治」等绝对化/违禁表述；
6) 每条控制在 60–320 字。
```

**关于 Loading 反馈**：现在用 `setInterval` 推进度条 + 三段式阶段文案。接真实接口后建议保留同一 DOM 结构，把进度推进改成「请求已发出 / 流式返回中 / 渲染完成」三态，流式输出（SSE）时可直接往 `.version-body` 追加文本。

## 4. 接入真实新闻抓取

`simulateFetch()`（一键抓取）与页面加载时的初始列表，替换为：

```http
GET /api/news/hot?range=24h&sources=all&category=all
```

若后端是定时任务（如每 5 分钟抓一次），前端只需轮询该接口并替换 `state.news`；`heat` / `growth` / `spark` 三个字段建议由后端直接算好，前端不做二次加工。

---

## 5. 接入真实发布（微博开放平台 / 矩阵号）

`publish()` 里的 `setTimeout(...)` 替换为：

```http
POST /api/weibo/publish
{ "account": "潮流好物研究所", "text": "…", "productId": "p1", "scheduledAt": "immediate" }
```

建议后端补三件事，前端无需改动：
1. 发布前二次跑一遍敏感词（前端校验是体验层的，不能作为合规底线）；
2. 返回真实 `weiboUrl` / `weiboId`，用于发布记录里的「查看微博」跳转；
3. 失败时返回错误码，前端在 `publish()` 的 catch 里 toast 提示即可。

## 6. 合规词库维护

前端词库在 `app.js` 顶部：

```js
const FORBIDDEN = ['最便宜','最低价','全网最','第一','国家级','顶级','唯一','极致','100%','永久','根治','绝对','史上最','包治'];
```

生产环境建议改为后端下发（`GET /api/compliance/words`），并按行业/平台分库，前端只负责展示命中结果与「一键优化」入口。

## 7. 上线前的建议改造清单

- [ ] 左右两栏布局在 1080px 以下已自动堆叠，但建议产品侧最低窗口宽度定为 1280px。
- [ ] `data.js` 中的商品图片位置现为 Emoji + 渐变占位，替换为真实 `imageUrl` 时，把 `.thumb` / `.mini-thumb` 的背景改为 `<img loading="lazy">`。
- [ ] 步骤状态目前存在内存中（刷新即重置）。若需要跨会话续接，把 `state` 的关键字段写入 `localStorage` 或后端草稿接口。
- [ ] 文案版本建议保留历史（`versions[].history`），方便反查「哪个版本带来了转化」。
