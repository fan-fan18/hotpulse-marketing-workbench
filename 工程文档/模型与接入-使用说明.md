# 模型与接入页 · 使用说明

模型相关的设置集中在这一页。它和工作台 Step 4 的「模型」快捷设置**共用同一份配置**（`config.model`）——两边改哪边都生效，不会各存一份。

入口：`admin.html#/model`

---

## 一、四个配置区块

### 1. 接入方式

| 方式 | 请求路径 | 说明 |
| --- | --- | --- |
| 本地模拟 | 不发网络请求 | 用本地模拟模型走完整流程，验证模板与链路 |
| 本地服务中转 | 浏览器 → 本机服务端 `/api/llm` → 服务商 | **推荐正式使用**：密钥放服务端环境变量 `HOTPULSE_API_KEY`，浏览器完全不接触密钥 |
| 浏览器直连 | 浏览器 → 服务商 `/chat/completions` | 可能被服务商的跨域策略拦截；密钥保存在本机浏览器 |

### 2. 服务商、接口地址与模型名

内置 8 个预设：OpenAI、DeepSeek、Moonshot 月之暗面、智谱 GLM、阿里通义千问、硅基流动、Ollama（本机部署）、自定义（OpenAI 兼容）。

**选服务商会自动填好接口地址与常用模型名**，例如：

| 服务商 | 接口地址 | 模型名（自动填第一个） |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Moonshot | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |

预设只是"帮你填一次"，覆盖后仍可手动改；每个服务商下面还有常用模型的快捷按钮，点一下即切换模型名。

### 3. 密钥、创作温度与输出方式

- **密钥**：输入框旁有明确警示——密钥只存在你本机浏览器（localStorage），页面代码不会上传到任何地方；**正式使用请走「本地服务中转」**，把密钥放在服务端配置里（启动服务端时设置 `HOTPULSE_API_KEY`），浏览器端留空即可。
- **创作温度**：滑块旁边直接给出不同任务的推荐值，并支持一键设为该值：

  | 任务类型 | 推荐区间 | 一键设为 |
  | --- | --- | --- |
  | 创作类（写文案、想标题） | 0.7 – 1.0 | 0.85 |
  | 改写 / 返工（照着清单改错） | 0.1 – 0.3 | 0.2 |
  | 抽取 / 评审 / 结构化输出 | 0 – 0.3 | 0.1 |

- **流式输出**：开关（原型里先记录配置，界面后续接逐字渲染）。
- **单价**：输入/输出单价（元 / 千 tokens），用于试运行与评测里估算花费，旁边标注"参考价，以服务商官网为准"。

### 4. 测试连接

真发一次最小请求（"只回复四个字：连接成功"），结果显示：

- 成功：耗时（ms）+ **实际响应的模型名** + 返回内容；
- 失败：人话原因（密钥无效 / 余额不足 / 模型名不存在 / 被限流 / 超时 / 网络不可达），原始响应收进折叠的「技术细节（可选）」；
- 本地模拟模式下会明确说明"不会发起真实网络请求"。

## 二、两边共用同一份配置是怎么做到的

```
后台「模型与接入」 ──┐
                    ├──> config.model（服务端 / 本机浏览器，三级配置同一份）
工作台 Step 4 快捷设置 ┘
```

- **后台改**：改的是草稿，点「保存配置」后写回当前生效的那一级。
- **工作台改**：在 Step 4「模型」区块里改接入方式 / 模型名 / 温度，会**立即写回同一份配置**并提示"已同步到服务端 / 本机浏览器"。
- **工作台生成前会重新读一次配置**：所以即使工作台页面没有刷新，后台刚改的模型名，下一次点「生成文案」就会用上。

工作台里还放了「去后台详细配置（服务商 / 密钥 / 测试连接）→」的入口，需要配密钥或测连接时直接跳过去。

> 另外，提示词页的「试运行」区块里也有一组紧凑的模型配置（接入方式 / 地址 / 模型 / 密钥 / 温度）——它改的同样是这一份配置，两处随时一致。

## 三、本次实测结果

`node tests/ui-model-tests.js` → **20 项通过 / 0 失败**（真实浏览器 + 本地服务 + 本地测试服务商）

**验收 1 · 后台改模型名并保存 → 工作台下一次生成就用新模型**

- 后台设为「浏览器直连 + stub-model」并保存，服务端配置确认 `mode=direct, model=stub-model`
- 打开工作台，Step 4 快捷设置里显示的正是 `stub-model`（同一份配置）
- **保持工作台页面不刷新**，在另一个标签页把模型名改成 `stub-model-v2` 并保存
- 回到原来那个工作台页面点「生成文案」：服务商侧实际收到的模型名是 `stub-model-v2`（4 次调用全部一致），结果区也标注了「模型 stub-model-v2 · 浏览器直连」

**验收 2 · 切换服务商时地址和模型名自动填好**

- 切到 DeepSeek → 地址 `https://api.deepseek.com/v1`、模型 `deepseek-chat`
- 切到 Moonshot → 地址 `https://api.moonshot.cn/v1`、模型 `moonshot-v1-8k`
- 预设之后手动改成自定义地址，草稿里保留手动值（预设不锁定）

**验收 3 · 错密钥 → 可读提示**

- 密钥填 `sk-bad-key` 点测试连接：提示「**密钥无效，请检查密钥是否正确、是否过期**」，耗时 14 ms
- 原始响应（HTTP 401 + `invalid_api_key`）收在「技术细节」折叠区里
- 换成正确密钥：提示「连接成功 耗时 5 ms 实际响应模型：stub-model」，并显示返回内容

**其它**

- 密钥警示文案包含"只存在你本机浏览器""本地服务中转""`HOTPULSE_API_KEY`"
- 温度推荐值表包含创作类 0.7–1.0、改写/返工 0.1–0.3、抽取/评审 0–0.3，点「0.85」滑块即变为 0.85
- 反向同步：在工作台把温度改成 1.35 → 服务端配置立刻变成 1.35 → 打开后台「模型与接入」，温度显示 1.35

## 四、这一轮顺带修掉的两处

1. **`HP.LLM.testConnection` 丢了**：早前重写调用层时只在试运行里直接用了 `call()`，测试连接函数没保留，这页做不了"测试连接"。已补回并支持 mock / 中转 / 直连三种方式。
2. **服务端中转的错误提示不够人话**：服务端返回的中文原因（例如"服务端没有可用密钥：请设置 HOTPULSE_API_KEY"）以前会被套上"HTTP 400 参数不合法"的通用提示，现在会优先展示服务端给的可读原因。
