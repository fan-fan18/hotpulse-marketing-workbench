# 评测体系与自动返工 · 使用说明

目标是每次改提示词后，能拿数据证明"确实变好了"，而不是凭感觉。这一部分**把评测核心做成了独立模块**（`assets/js/core/eval.js`），工作台与后台都直接调用同一份逻辑，不存在两套口径。

---

## 一、核心与界面分离

```
assets/js/core/eval.js   ← 评测与返工内核（无界面依赖）
   ├─ HP.Eval.machineCheck(copy, material, limits)   机器校验（8 项）
   ├─ HP.Eval.materialFrom(news, products, opt)      从业务数据构造评测素材
   ├─ HP.Eval.buildReviewPrompt(copy, materialText)  评审提示词（后台可配）
   ├─ HP.Eval.parseReview(raw)                       评审结果容错解析
   ├─ HP.Eval.totalScore(machine, review, weights)   加权总分
   └─ HP.Eval.autoRework({copy, material, ...})      自动返工
```

调用方：

| 调用方 | 用途 |
| --- | --- |
| 工作台 Step 4 | 每个候选版本生成后立刻校验、显示分数与明细、可选自动返工 / 一键修正 |
| 工作台 Step 5 | 合规审核清单与"机器校验 N 分"直接用同一内核 |
| 后台评测台 | 批量评测、返工、历史对比都会复用同一份内核 |

---

## 二、机器校验（8 项）

| 检查项 | 类型 | 权重 | 判定说明 |
| --- | --- | --- | --- |
| 广告法违禁词 | **硬伤** | 5 | 命中即失败，并列出命中了哪几个词。词库覆盖需求点名的 16 个：最佳、最好、最低、第一、国家级、顶级、绝对、永久、百分百、全网最低、唯一、首选、冠军、领导品牌、完美、万能（另含 100%、全网最、史上最、包治、根治） |
| 编造价格 | **硬伤** | 4 | 抓出文案里出现的所有金额，必须都能在素材里找到；失败时同时列出"编造的金额"和"素材里真实可用的金额" |
| 字数区间 | 瑕疵 | 2 | 是否落在后台配置的 `minWords–maxWords` |
| 话题标签 | 瑕疵 | 1.5 | 是否带齐素材指定的话题，且总数不超过上限 |
| 表情符号数量 | 瑕疵 | 1 | 是否在建议区间内 |
| 互动引导 | 瑕疵 | 1 | 结尾是否有评论 / 私信 / 点赞类引导 |
| 排版残留 | 瑕疵 | 1 | 是否残留 Markdown、代码块、`{{占位符}}`、超长空行 |
| 是否提到商品 | 瑕疵 | 1 | **不参与返工**（改了也白改） |

分数 = 通过项权重之和 ÷ 总权重 × 100；命中硬伤会置 `hardFail = true`（总分再高也不算通过）。

**金额台账的口径**：素材允许的金额分两类，检查失败时会把两类都说清楚——

```
文案出现素材里没有的金额：¥88、¥999；
素材里真实可用的金额：¥89、¥199、¥299、¥369、¥599、¥799
（另有可由「原价 − 售价」推出的：¥110、¥300、¥430）
```

即：商品售价与原价必须原样来自素材；「省了多少」这类由原价减售价能推出的金额也算合规，但会单独标注，避免把合理推导误判成编造。

## 三、模型评审

- 四个维度各 1–5 分：**热点关联度、素材还原度、传播吸引力、语气自然度**，外加一句话点评；
- 用配置里的**低温度**（默认 0.2），保证打分稳定；
- 提示词在后台「提示词与模板」页的**「返工说明与模型评审提示词」**区块可编辑（`{{素材}}` / `{{文案}}` 两个占位符），旁边有**评审提示词预览**，改一个字预览立即跟着变，保存后写回配置；
- **解析容错**：代码块包裹、前后有解释、中文键名、散乱写法（`热点关联度：4分`）都能捞回来；实在解析不了就标记这条评审失败并跳过，不中断整轮。

内核入口：`HP.Eval.runReview({copy, materialText, products, config, llm})` —— 拼提示词 → 用低温度真调一次 → 容错解析，返回

```js
{ ok:true, dims:{hot, material, appeal, natural, comment}, avg:3.75, score:75, raw:'…', latencyMs:275, model:'…' }
// 或
{ ok:false, reason:'模型返回的内容无法解析成评分结构（已跳过这条评审，未中断整轮）' }
```

**工作台里怎么用**：每个候选版本下方有「模型评审」按钮，点一下出四维分、均分与点评；生成参数区有「生成后同时跑模型评审」开关（默认关闭，省调用成本），打开后每个版本会自动带上评审结果。综合分 = 机器分 × 权重 ＋ 评审分 × 权重，卡片上直接写成 `机器 100 × 0.5 + 评审 90 × 0.5 → 综合 95`。

## 四、总分

机器分与评审分按权重合成，**默认各占一半**，权重可调：

- 工作台「质量校验与自动返工」里直接给两个输入框：`机器 0.8 ＋ 评审 0.2`，改一边另一边自动补齐到 1（归一化），改完立即用新权重重算卡片上的综合分，并写回共用配置；
- 版本卡上会把算式写出来：`机器 100 × 0.5 + 评审 90 × 0.5 → 综合 95`；
- **不启用评审时以机器校验分为准**（此时权重自动视为 1 : 0）。

## 五、自动返工

1. 只把**改了有用**的问题送去返工（字数、违禁词、编造价格、话题标签、互动引导、表情数量、排版残留）；
2. 返工提示里带上"未通过清单 + 素材 + 待修改文案"，并且**把完整写作规范一起传给模型**（返工也要守同一套规则）；
3. 返工用**低温度**（`prompt.reworkTemperature`，默认 0.2）——照着清单改错，不需要发挥；
4. 改完重新校验，**只有分数提升才采纳**；分数没涨就保留上一版，防止越改越差；
5. 全过程可追溯：第几轮、每轮修好了什么、还剩什么没解决，都记录在返工轨迹里。

**返工说明放在提示词配置里**：后台「提示词与模板」页的「返工说明与模型评审提示词」区块可以改这段说明，旁边还有**返工提示预览**——把"引导语 + 未通过清单 + 素材 + 待改文案"的完整结构展示出来（含具体失败原因示例），改一个字预览立即变，保存后写回配置。

## 六、工作台里的落地

**Step 4 每个候选版本**下方新增一行：

```
机器校验 100 分   全部通过   自动返工 69.7 → 100（1 轮，共 1 次尝试）   收起明细 | 一键修正（1 项）
```

点「校验明细」展开 8 项逐条结果（含权重、可返工/不返工标记）；点「一键修正」只针对该版本未通过项返工，改不好则保留上一版。

生成参数区新增「质量校验与自动返工」：开关 + 最多轮数（与后台配置共用同一份，改哪边都生效）。

**Step 5 合规审核**用同一内核：清单项就是上面那 8 项，风险徽章带上「机器校验 N 分」，硬伤会拦住"通过审核"，「一键优化风险表述」走的也是返工内核。

- 8 项检查齐全；构造违规文案（超字数 + 违禁词 + 编造价格 + 缺话题 + 缺互动 + 排版残留）→ **全部揪出**，机器分 6.1，`hardFail=true`

- 违禁词逐词验证：需求点名的 16 个词**全部覆盖**且逐个单独命中（词库共 21 个）
- 编造价格台账：`文案出现素材里没有的金额：¥88、¥999；素材里真实可用的金额：¥89、¥199…（另有可由「原价 − 售价」推出的：¥110、¥300…）`

## 八、这一轮顺带修的两处

1. **返工时看不到写作规范**：返工调用原先只传角色设定，导致返工出来的文案可能违反"结尾必须以提问结尾"这类规则。现在把完整规范（角色 + 写作规范）一并传给返工，返工也守同一套规则。
2. **测试无法区分生成与返工调用**：测试用服务商只记录请求，自动返工上线后"调用次数 = 风格数"不再成立。现在按请求里是否含「未通过清单」区分 `compose` / `rework`，测试同时能报告"额外发生了几次返工调用"。

> 配置项：`evalConfig.autoRework`（是否自动返工）、`evalConfig.maxReworkRounds`（最多轮数）、`evalConfig.weights`（机器/评审权重）、`prompt.reworkTemperature`（返工温度）。改默认值后记得执行 `node scripts/gen-defaults.js`。
