# HotPulse 配置后台 · 外壳说明

在工作台之外新增的独立后台。本次只搭 **外壳**：顶栏、左侧两组导航、卡片式分节内容区、底部固定操作栏、三级配置读取与数据来源徽章。各页的具体功能以占位区块的形式标出，后续往里填。

---

## 一、怎么打开

后台是独立入口 `admin.html`，两种打开方式对应两种数据来源：

| 方式 | 操作 | 数据来源徽章 |
| --- | --- | --- |
| 不启动服务（最简单） | 直接双击 `admin.html` | **本机浏览器**（配置存在浏览器 localStorage） |
| 启动本地服务 | 在项目目录执行 `node server/server.js`，浏览器打开 `http://localhost:8787/admin.html` | **服务端**（配置写在 `data/config.json`） |

> 工作台入口不变：`index.html`（后台顶栏右侧「返回工作台」即跳回它）。
> 服务端同时托管两个页面，所以启动后也可以直接用 `http://localhost:8787/index.html` 打开工作台。

---

## 二、三级配置读取（本后台的公共约定）

读取顺序固定为 **服务端 → 本机浏览器 → 内置默认值**，拿得到哪级就用哪级：

1. **第 3 级 · 服务端**：通过 http(s) 打开页面时，先请求 `GET api/config`。成功即采用服务端配置，保存也会写回服务端。
2. **第 2 级 · 本机浏览器**：服务端不可用（或直接用 `file://` 打开）时，读 `localStorage` 里的 `hotpulse.config.v1`。首次读取时会把内置默认值落一份到本地，后续修改都存在本地。
3. **第 1 级 · 内置默认值**：浏览器存储被禁用／不可写时，退回页面内置的默认配置（只读兜底）。

顶栏徽章会明确写出当前生效的是哪一级，右侧三格指示器同时显示级别高低（1 格＝内置默认值，2 格＝本机浏览器，3 格＝服务端）。鼠标悬停徽章可以看到读取顺序与最近一次服务端保存时间。

「配置总览」页会把当前来源、服务端状态、保存目标、存储键、服务端自动补齐的区块都列出来，方便一眼确认。

## 三、页面与区块

左侧导航分两组：**本页配置区块**（点击滚动到对应位置）与**其它后台页面**（页面间互相跳转）。

| 页面 | 配置区块（后续填充内容） |
| --- | --- |
| 配置总览 | 数据来源 / 三级读取说明 / 后台页面清单（本页已可用） |
| 提示词与模板 | 角色设定与写作规范 / 素材模板 / 单件商品呈现格式 / 实时预览与试运行 |
| 创作风格与语调 | 创作风格 / 语调预设 |
| 模型与接入 | 接入方式 / 服务商与地址 / 密钥与温度 / 测试连接 |
| 商品库 | 统计概览 / 商品列表 / 新增与编辑 / 批量与导入导出 |
| 抓取来源 | 来源列表 / 测试全部来源 / 合规与风险规则 |
| 评测台 | 用例管理 / 跑评测 / 历史与对比 |

每个区块都是「标题 + 一句说明 + 内容区」的卡片；未实现的区块会显示一条待填充清单，说明这里将来放什么。

## 四、底部固定操作栏

滚动时固定贴在窗口底部，不随内容消失，包含：

- **保存配置**（主操作，`Ctrl` + `S` 同效）：写回当前生效的那一级，并提示写到了服务端还是本机浏览器；写服务端时会先备份上一版。
- **撤销未保存改动**：丢弃草稿，回到已保存的配置。
- **导出配置**：导出 JSON 配置文件。
- **导入配置**：导入前校验格式，坏文件会给出明确错误且不影响原配置。

状态区会显示「已保存／有未保存的改动」，改动未保存时整条操作栏变成暖色提示。

其它快捷键：`Alt` + `1`~`7` 切换后台页面，`Esc` 关闭弹窗。

## 五、服务端接口与目录

```
server/server.js        零依赖 Node 服务（静态托管 + 配置接口）
server/defaults.json    由 scripts/gen-defaults.js 从内置默认值生成，保证服务端与前端同源
data/config.json        服务端配置文件（首次写入时自动创建）
data/backups/           每次写入前的自动备份，保留最近 10 份
```

| 接口 | 说明 |
| --- | --- |
| `GET /api/health` | 健康检查，返回配置文件路径 |
| `GET /api/config` | 读取配置；缺失的段落会用默认值补齐，并在 `filled` 里说明补了哪些 |
| `PUT /api/config` | 写入配置；先备份上一版，商品列表或角色设定为空会被拒绝 |
| `GET /api/config/backups` | 列出备份文件 |

改了内置默认值后（`assets/js/core/config.js`），执行 `node scripts/gen-defaults.js` 重新生成 `server/defaults.json` 即可保持两边一致。

## 六、本次实测结果

逻辑测试 `node tests/shell-tests.js`：**17 项通过 / 0 项失败**

- 不启动服务 → 徽章「本机浏览器」（第 2 级），配置自动落到 localStorage，保存也写本地
- 服务端不可用且浏览器存储被禁用 → 退回「内置默认值」（第 1 级）
- 启动服务 → 徽章「服务端」（第 3 级）；服务端优先于本机浏览器
- 保存写回服务端，第二次保存留下上一版备份；重新读取拿到刚保存的值
- 商品列表为空 → HTTP 400 拒绝写入，原配置不受影响
- 手动删掉服务端配置里的 `tones`、`model` 两段 → 重新读取时自动补齐

UI 测试 `node tests/ui-smoke.js`（真实 Chrome）：**11 项通过 / 0 项失败**

- 7 个后台页面互相跳转正常，标题与地址栏一致；返回工作台入口指向 `index.html` 且目标存在
- 左侧区块导航点击可滚动定位（实测 scrollY=312）
- 底部操作栏 `position: fixed`，滚动到页面底部仍可见
- 不启动服务：徽章「本机浏览器」；启动服务：徽章「服务端」，级别指示器点亮 3 格
- 保存后状态栏与提示显示写回「服务端」，服务端配置文件可读回，全程无前端脚本报错

> UI 测试脚本依赖本机 Chrome 与 playwright-core（仅测试用），产物本身不引任何第三方库、不需要构建步骤。
