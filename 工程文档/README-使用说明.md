# 热点引擎 HotPulse · 电商媒体热点营销工作台（Web 原型 Demo）

从「新闻抓取」→「热点商品匹配」→「LLM 微博文案生成与审核发布」的全流程闭环原型，
外加一个独立的**配置后台**（含**文案评测台**），用来把写死在代码里的提示词、商品库、
抓取来源、模型设置都搬到页面上由运营维护；再往上一层是**运营效率**：
定时抓取 + 热点去重 + 选题池排期 + 待审队列键盘审核 + 批量生成 + 数据看板。

技术约束：**不引第三方库、没有构建步骤**。工作台与后台双击即可打开；本地服务端只用 Node 内置模块。

---

## 一、三个入口

| 入口 | 打开方式 | 说明 |
| --- | --- | --- |
| 工作台 | 双击 `index.html`，或启动服务端后 `http://localhost:8787/index.html` | 5 步业务流程主线 |
| 配置后台 | 双击 `admin.html`，或 `http://localhost:8787/admin.html` | 7 个配置页；顶栏右侧「返回工作台」跳回 |
| 本地服务端 | 在项目目录执行 `node server/server.js`（默认 8787 端口，可跟一个端口号参数） | 托管两个页面 + 配置读写 `/api/config` + 模型中转 `/api/llm` + 来源抓取测试 `/api/sources/test` + 热点池 `/api/news`（含定时抓取） |
| 一键启动 | 双击项目根目录的 **`启动服务.bat`** | 检查 Node → 起服务端 → 2 秒后自动打开工作台；关窗口即停 |

推荐 Chrome / Edge，窗口宽度 ≥ 1280px 体验最佳。

## 二、配置从哪来（三级读取，后台顶栏徽章会写明当前是哪一级）

1. **服务端**（最高优先级）：用 http(s) 打开且 `GET api/config` 成功 → 用服务端配置，保存也写回 `data/config.json`。
2. **本机浏览器**：服务端不可用（或直接 `file://` 双击打开）→ 读 `localStorage` 的 `hotpulse.config.v1`。
3. **内置默认值**：浏览器存储不可写时退回页面内置默认值（只读兜底）。

服务端侧还有三条保护：**写入前自动备份上一版**（`data/backups`，保留最近 10 份）、
**读取时自动补齐缺失区块**（误删一段也不会把工作台弄崩）、**关键内容为空拒绝写入**（防止一次误操作清空商品库）。

## 四、工作台 5 步流程怎么走（演示脚本）

> 快捷键：`Alt + 1~5` 在 5 个步骤间快速切换。

| 步骤 | 你会看到 | 建议操作 |
| --- | --- | --- |
| Step 1 新闻抓取 | 统计卡 + 抓取控制 + 实时热点列表 | 点「一键抓取」体验抓取反馈；**点击任意热点卡片**选为本次营销主线 |
| Step 2 建议匹配商品 | 热点简报 + 系统推荐商品卡（含匹配度与推荐理由） | 点「采纳并绑定」选 1–3 件，自动流入 Step 3 |
| Step 3 匹配商品 | 深度筛选（关键词 / 价格区间 / 最低评分 / 类目）+ 商品库 + 已绑定商品库 | 勾选或点行绑定；在右侧把某件**设为主推** |
| Step 4 创作文案 | 生成参数（风格 / Emoji 强度 / 话题标签 / 语调 / 附加要求）+ 多个候选版本 | 点「生成文案」有 Loading（每个创作风格独立跑一次，各出一个候选版本）；可复制、选用、微调、送审 |
| Step 5 审核并发送 | 微博卡片预览 + 质量校验明细 + 返工轨迹 + 发布配置 | 「一键修正」自动返工 →「通过审核」→「一键发送」→ 二次确认 → 模拟发布成功 |

上下文的贯穿方式：顶部上下文条跟随 **当前热点 → 已绑定商品数 → 候选版本数 → 发布状态**；
改上游（换热点、改绑定商品）会自动清掉下游旧文案与审核状态，避免"文案对应的是上一件商品"。

## 五之二、运营效率（顶部导航后三个视图）

工作台的顶部导航现在是真的能切的四个视图：

| 视图 | 看什么 / 干什么 |
| --- | --- |
| 营销工作台 | 原来的 5 步主线；Step 1 卡片左侧可**勾选多条**做批量生成，卡片上的「+ 选题池」把热点排进选题池 |
| 商品库 | 只读的商品全景（与工作台同款商品卡），点「带入工作台绑定」直接进 Step 3 |
| 内容中心 | 选题池：状态流转（待办/进行中/已发/搁置）、月历排期、同热点撞车提示 |
| 数据看板 | 抓取段（服务端热点池）+ 生产审核段（本机工作区）指标、抓取趋势、涨得最快、审核漏斗 |

配套的三件事：

- **定时抓取**：服务端每 N 分钟抓一次启用中的来源 → 按标题指纹去重 → 记热度采样 → 落 `data/news.json`；
  工作台卡片上会显示"被 N 个来源抓到"和真实涨幅。
- **待审队列**：批量生成的文案全部进队列，Step 5 右侧可点开，键盘 `J/K` 翻页、`A` 通过、`R` 打回（必须填原因）。
- **批量生成**：热点 × 风格，并发默认 3（最多 6），可中途停止；开跑前先算任务数与预估耗时。

细节（去重规则、趋势算法、日历、撞车口径、看板每个数字的来源、发布后链接能追踪到什么）见
`运营效率-使用说明.md`。

## 六、评测与自动返工（一句话版）

一段文案会同时过两关：**机器校验 8 项**（字数 / 话题标签 / 表情数量 / 广告法违禁词 / 编造价格 /
互动引导 / 排版残留 / 是否提到商品，其中违禁词与编造价格是**硬伤**、权重最高）与
**模型评审四维**（热点关联度 / 素材还原度 / 传播吸引力 / 语气自然度，低温度打分、解析容错）。
两关按权重合成总分（默认各半）。

没过线时**自动返工**：只把"改了有用"的问题连同一句话说明送回给模型改，温度调低；
**只接受改好的版本**（分数没涨就保留上一版），并留下"改了几轮 / 每轮修好什么 / 还剩什么"的轨迹。
全部逻辑在工作台 Step 5 与后台评测台共用。

## 七、接真实模型（两种方式，都不改代码）

1. **后台页面里配**：打开「模型与接入」，选服务商（地址与常用模型名自动填好）→ 填密钥 → 点「测试连接」，
   看到"连接成功，实际响应模型：xxx"即可；工作台下一次生成立刻用新模型。
2. **服务端环境变量**：密钥放服务端，接入方式选「本地服务中转」，浏览器里不出现密钥
   （页面上也会提示"密钥只存在你本机浏览器，正式使用请走服务端中转"）。

常见服务商预设：OpenAI、DeepSeek、Moonshot、智谱 GLM、阿里通义千问、硅基流动、Ollama（本机）、自定义 OpenAI 兼容地址。

## 九、已知边界（Demo 定位）

- 内置热点、商品、发布结果都是模拟数据；「抓取服务在线」「自动刷新」是状态展示，未接真实定时任务。
- 未配置密钥时，模型调用走**本地模拟**：会读同一份提示词、按规范约束产出文案，
  并在界面上明确标注"模拟输出，不代表真实模型效果"。
- 公开热榜接口只适合原型演示，正式上线应改用官方开放平台或商业舆情服务，并遵守对方的爬虫协议与服务条款。
- 试运行 / 评测只用于调试，不会写回工作台。

## 十、抓取到底抓了什么（先看这一节，能省很多时间）

**状态灯不再永远显示"在线"**：双击 `index.html` 打开时是 **演示模式 · 未连接服务端**（黄色）；
只有启动 `node server/server.js` 并用 `http://localhost:8787/index.html` 打开，才显示**抓取服务在线**。

| | 演示模式（file://） | 服务端模式（http://localhost:8787） |
| --- | --- | --- |
| 「一键抓取」 | **不真抓**，只重新渲染已有条目，并明确提示"演示模式：没有真的抓取" | **真抓**：服务端访问启用中的来源，解析到的条目写回配置并出现在列表（提示给出成功来源数与写入条数） |
| 列表里的新闻来自 | 内置 8 条演示新闻（按启用的来源过滤）+ 已经抓到的订阅条目 | 同上 |
| 统计卡 | 全部是真实数字：「当前热点列表 N 条」「启用来源 X 个 · 其中有条目 Y 个」「最近抓取 时间/—」 | 同上 |

**列表为空时，页面会直接告诉你原因**（不再只说"没有匹配的热点"），并给两个按钮：
「恢复并启用内置来源」（把内置 8 个来源补回并启用，运营自己加的自定义来源不会被删）和「去后台配置来源」。

**内置来源丢了会自动补回**：内置来源在界面上只允许"停用"、不允许删除，所以在读取配置时，
如果发现某个内置来源**整条不见了**（旧配置、导入丢字段、被别的工具改坏），会自动按 id 补回来并启用，
并在页面上提示"检测到配置里缺少 N 个内置来源……已自动补回并启用"（后台「配置总览」也会提示）。
注意区分：来源**还在**、只是被停用的，会尊重这个停用设置，不会自动打开。

> 举例：配置里只剩「微博热搜榜」「百度热搜榜」两个自定义订阅源（内置 8 个整条丢失）时，
> 打开页面会自动补回内置来源，热点列表直接回到 8 条，不需要手工配置。

两个常见坑：

1. 在后台把内置来源停用、只留自定义订阅源 → 列表就空了。自定义订阅源必须先在服务端模式下「一键抓取」抓到条目，才会有新闻。
2. 微博热搜榜 / 百度热搜榜这类公开榜单是前端渲染 + 反爬的，**即使启动服务端也拿不到标题**，属于预期；请改用 RSS / JSON 订阅源。
