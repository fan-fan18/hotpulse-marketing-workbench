## 0. 先说清楚「真实模型」这件事

这台机器上**没有任何模型密钥**（实测：`OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`DASHSCOPE_API_KEY`、
`MOONSHOT_API_KEY`、`ZHIPU_API_KEY`、`HOTPULSE_API_KEY` 六个环境变量全部未设置；服务端配置里
`model.mode = mock`、`apiKey` 长度 0）。所以"真实模型"这一项按下面两种方式落地，边界写清楚，不含糊：

| 做法 | 是不是真模型 | 实测到了什么 |
| --- | --- | --- |
| **A. 本地 OpenAI 兼容服务端**（`tests/stub-provider.js`，端口 8834） | 不是真模型，但**是真实 HTTP 链路** | 真的发 `POST /v1/chat/completions`；真的处理 401 / 402 / 404 / 429 状态码；真的读响应里的 `usage` 算钱；真的统计耗时。按素材拼出一段**合规**文案返回（不编价格、不带违禁词、字数落在素材声明区间内） |
| **B. 真实服务商探测**（`tests/provider-probe.js`，故意用错密钥） | 是真实服务商 | 见下表：4 家能建连并返回 HTTP 状态码，全部因为密钥错被拒 → **外网与接口地址都没问题，只缺密钥** |

真实服务商连通性探测结果（故意用一个写错的密钥，只为验证连通性与错误映射，不消耗额度）：

| 服务商 | 实际 HTTP 状态 | 界面里给运营看的人话 |
| --- | --- | --- |
| DeepSeek | 401 | 密钥无效或没有该模型的调用权限（147 ms） |
| 智谱 GLM | 401 | 密钥无效或没有该模型的调用权限（104 ms） |
| 阿里通义千问 | 401 | 密钥无效，请检查密钥是否正确、是否过期（136 ms） |
| Moonshot 月之暗面 | 401 | 密钥无效或没有该模型的调用权限（229 ms） |
| OpenAI | 网络层失败 | 调用失败：fetch failed（10673 ms，本机网络环境访问不到） |

**换成真模型的成本＝零改代码**：

1. 设一个环境变量（`HOTPULSE_API_KEY` / `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` /
   `MOONSHOT_API_KEY` / `ZHIPU_API_KEY` 任意一个），`acceptance-tests.js` 会自动检测并切换到真实服务商，
   并把**实际用的模型名**打印出来；或
2. 打开后台「模型与接入」，选服务商（地址与常用模型名自动填好）、填密钥、点「测试连接」，
   看到"连接成功，实际响应模型：xxx"即可。工作台下一次生成立刻改用新模型。

> 也就是说：**验收 1~5 的链路、评分逻辑、返工逻辑、对比逻辑全部是真实跑的**；
> 唯一"非真实"的地方是——被评测的那段文案由本地兼容服务端产生，而不是某家商业模型产生。
> 这一点在报告与界面上都标注了（试运行时本地模拟模式会明确写"现在是模拟输出，不代表真实模型效果"）。

## 6. 这轮实测中发现并顺手修掉的 3 个问题

1. **评测台"参与的创作风格"界面与预估不一致**：页面把 4 个风格都画成"已选中"，实际只跑第 1 个，
   导致"开跑前预估任务数"比看到的少，运营会以为跑漏了。
   已改成"一个都没点过时按全部参与"，界面高亮、预估任务数、实际派发三者一致。
2. **A/B 指标表里的"总消耗"没有单位**（取的是花费元值，容易被误读成 tokens）：改名为
   **「总花费」并带单位"元"**。
3. **新增 `stub-slow` 模型名**（每条请求慢 600 ms），让"中途叫停"能被稳定复现和验证。

另外把本地兼容服务端从"只回一段固定文本"升级为"按素材拼合规文案 + 对评审请求返回四维评分 JSON"，
这样真实 HTTP 链路上也能跑出有意义的汇总数字（此前评审均分是空的、通过率 0%）。
