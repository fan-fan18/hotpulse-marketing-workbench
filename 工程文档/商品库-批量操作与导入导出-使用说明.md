# 商品库：批量操作与导入导出 · 使用说明

这一轮给商品库补上两件事：**多选后的批量操作**（批量改品类 / 批量删除，删除带引用检查与二次确认）与**两种格式的导入导出**（JSON 结构化数据 + CSV 表格文件）。

---

## 一、批量操作

### 怎么多选

- **表格视图**：每行最左侧有勾选框；表头勾选框是"全选当前列表"（只影响当前筛选出来的行）。
- **卡片视图**：每张卡片右上角有勾选框（点勾选框不会触发"点卡片编辑"）。
- 选中任意数量后，列表上方出现**批量操作栏**：`已选 N 件`＋「其中 M 处热点推荐引用了这些商品」＋ 批量改品类 / 批量删除 / 取消选择。

### 批量修改品类

在批量栏里填目标品类（可从已有品类下拉选，也可直接输入新品类）→ 点「批量修改品类」。

完成后弹出结果反馈：

```
批量修改品类完成   目标品类：实测批量品类
✓ 成功 3 条；跳过 0 条
```

如果某些商品本来就是该品类，会被跳过并说明原因，例如：

```
成功 0 条；跳过 3 条
跳过原因：· 三合一防风冲锋衣 加绒可拆内胆：品类本来就是「实测批量品类」 …
```

列表和顶部统计（商品总数 / 品类数 / 价格区间 / 平均折扣率）会同步刷新。

### 批量删除

点「批量删除」后是**二次确认**，确认框里会先做**引用检查**：

```
确认删除这 1 件商品？
引用检查：有 1 处热点推荐引用了这些商品，删除后这些推荐会失效。另有 7 处语义匹配会带上它们。

商品                     被热点推荐引用      涉及热点
三合一防风冲锋衣 加绒可拆内胆   1 条             冷空气来袭！北方多地气温骤降 10℃…
                           语义匹配 7 条
```

两个保护：

- **点取消不会删任何东西**；
- 如果一次把整个商品库都选中要删，会被直接拦住（"不能清空商品库"）。

删除完成后同样给结果反馈（成功几条 / 跳过几条及原因），并提示"相关热点推荐已同步失效"。

### 删除之后工作台会怎样

1. 预设的热点-商品推荐关系里不再出现该商品（推荐列表自动少一件）；
2. 语义匹配也不会带上它（它已经不在商品库里）；
3. 如果这件商品此前在工作台被"绑定"过，工作台会自动清理这条失效绑定，并提示「有 N 件已绑定的商品已从商品库删除，已自动移除」，页面不会报错；
4. 工作台切换到 Step 2 / 3 / 4 时会顺手同步一次配置，所以后台删完保存后，工作台**不用刷新**就能反映过来。

## 二、导入导出

### 两种格式

| 格式 | 用途 | 保真程度 |
| --- | --- | --- |
| **结构化数据文件（JSON）** | 备份、迁移 | 完整保真：编号、品牌、SKU、库存、销量、转化率、评分、渐变等全部字段 |
| **表格文件（CSV）** | 运营用 Excel / WPS 批量编辑 | 六列业务字段；导入时同名的商品会沿用原编号 |

### CSV 的格式约定

- 表头固定为：`名称,售价,原价,品类,卖点,图标`
- 卖点一列用**顿号**分隔多个卖点
- 字段里含逗号、引号或换行时，会自动用引号包裹；字段内的引号会转义成 `""`
- 文件带 **BOM**、用 **CRLF** 换行 —— 用 Excel / WPS 直接双击打开不乱码

### 导入流程（先校验，再让人决定）

1. 选择文件后先解析并**逐行校验**；
2. **有问题**：弹出报告，列出**第几行、什么问题**（例如"第 2 行：售价必须是大于 0 的数字（当前：-5）"），并明确写着「导入已阻止，原有商品库未受影响」；
   - 这时可以「取消，我去改文件」，也可以选择「**仅导入通过校验的 N 行**」（跳过有问题的行）——由运营决定；
3. **全部通过**：给出可导入行数与预览表格，再选导入方式：
   - **替换整个商品库**（同名商品沿用原编号）
   - **追加到现有商品库**（自动分配不重复编号）
4. 导入完成弹窗给出「成功导入 N 条；跳过 M 条」，并提醒"还**没保存**，确认无误后点底部保存配置"。

无论哪一步失败，都**不会导一半留下半套脏数据**。

## 三、本次实测结果

### 界面验收 `node tests/ui-product-batch-tests.js` → **34 项通过 / 0 失败**

**批量操作（验收 1）**：勾选 3 件 → 批量栏显示「已选 3 件」→ 批量改成「实测批量品类」→ 结果「成功 3 条；跳过 0 条」；列表前三行品类全部变为新品类；**统计的品类数从 7 变为 8，与列表实际一致**。重复执行同一操作走跳过分支：「成功 0 条；跳过 3 条」并逐条说明"品类本来就是…"。取消选择后批量栏收起，撤销后回到原始 7 个品类。

**删除引用检查（验收 2）**：p1「三合一防风冲锋衣」被 1 条热点引用 → 确认框显示「有 1 处热点推荐引用了这些商品，删除后这些推荐会失效」+ 表格里「1 条 / 语义匹配 7 条 / 涉及热点：冷空气来袭…」；点取消后商品数仍为 20；再确认删除 → 结果「成功 1 条」→ 保存后服务端 20 → 19 件。

**删除后回工作台（验收 3）**：冷空气这条热点的推荐里不再出现 p1（推荐 8 件，不含 p1），页面无脚本报错；另外验证了"已绑定商品被删"的场景——工作台自动清理失效绑定并提示原因，页面同样不报错。

**导出再导入（验收 3）**：导出 JSON（9613 字节 / 20 件）→ 导入前报告"全部通过"→ 替换导入 → **草稿与服务端原内容逐字段完全一致**。

**表格往返（验收 1）**：导出 CSV → 校验 BOM + 中文表头 + CRLF + 行数（20 行数据）；模拟"用表格软件改几行"（第 1 件售价 299→288、第 2 件卖点替换）再导入 → **两处改动都生效，其它商品保持不变**。

**负价格文件（验收 2）**：构造含负价格与原价低于售价的文件 → 报告里能看到「第 2 行（负价格商品）：售价必须是大于 0 的数字（当前：-5）」「第 3 行：原价（199）不能低于售价（299）」→ 明确提示导入已阻止、原有商品库未受影响 → 商品数没有变化。

### 内核实测 `node tests/products-core-tests.js` → **20 项通过 / 0 失败**

覆盖 CSV 表头/BOM/CRLF、引号包裹与字段内逗号、`""` 转义、坏表头说明、导出再导入一致性（CSV 与 JSON）、坏 JSON 报错、引用检查与语义匹配打分。

## 四、这一轮修掉的三个真实缺陷

1. **批量栏拿不到数据**：`paint()` 里局部变量名重复声明（`var all`），把"商品数组"覆盖成了"全选复选框"，导致批量栏和统计都取到错误对象。已改名并复测。
2. **链式弹窗被清掉**：外壳的弹窗在按钮回调执行后会无条件关闭自己；像"确认删除 → 结果反馈"这种在一个弹窗里再开一个弹窗的流程，新弹窗会被旧弹窗的关闭动作一起清空。现在只有在回调没有打开新弹窗时才关闭。
3. **导出按钮点了没反应**：外壳没有把 `download` / `stamp` 暴露给页面模块，商品库的导出按钮调用时报错。已补上导出。

另外顺带修了一处体验问题：工作台以前只在"生成文案"时同步配置，切到 Step 2 / 3 / 4 时不会；现在切步骤也会同步一次，后台改完商品库不用刷新工作台。

> 测试依赖提醒：浏览器测试需要 `playwright-core`，安装命令 `npm install playwright-core --prefix .test-tools --no-save`（脚本会自动在该目录查找）。
